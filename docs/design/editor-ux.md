# 场景编辑器：舒适度设计

> 目标不是“做一个低代码平台”，而是让 **spec-owned 场景的结构编辑**
> 像在图上改东西，而不是在长表单里翻找。可编辑性只控制“能不能保存”，
> 不控制“能不能看”。

## 1. 不变量（来自项目设计意图）

- **单一权威**：`spec-owned → eject to code → code-owned`。结构是数据，
  函数是代码；不做代码反向生成 spec。
- **三层可编辑性**：
  - L1 结构：节点、边；
  - L2 参数：`ParamSpec`（prompt、工具、步数、预算等）；
  - L3 策略：内置中间件只允许开关 + 参数，顺序由 slot 与不变量保证，
    **不能拖**；自定义块 / 改顺序必须 eject。
- **画布只改拓扑 + 位置**：节点身份、参数、校验、版本在 Python 侧；
  画布回传 JSON 一律当不可信输入，必须过 `merge_canvas`。
- **删节点不自动重连**：悬空边显式报错；code-owned 场景只能拖布局，
  改不了结构。
- **场景是一等对象**：router 只是其中一种；保存后应能直接跑任务、用例、
  评测，编辑器不是孤立的玩具。

## 2. 当前为什么“不舒服”

1. **一页到底**：基本信息、工作流、画布、选中节点参数、策略、版本、预览、
   保存全部纵向堆叠；改参数要往下滚，画布离开视线。
2. **检查器在画布下方**：画布与参数不能同屏，选中节点后没有“就地编辑”的感觉。
3. **没有撤销/重做**：点连线即删、点 × 即删节点，误操作只能重来。
4. **不能多选 / 复制 / 键盘操作**：只能逐个拖；删除节点靠 9px 的小 ×。
5. **画布固定 1180×470，不能缩放/平移**：节点 x 还被限制在 920，大图很挤。
6. **没有脏状态和草稿保护**：切换场景会重新载入，未保存改动会丢。
7. **保存 → 校验 → 跑用例是断开的**：编辑器的核心价值“改完立刻证明有没有
   改坏”需要切到质量页手动跑。

## 3. 目标：工作台（Workbench）

```text
┌ 场景头：名称 / 归属 / 未保存 ● / 保存并验证 ──────────────┐
│ 块库      │            画布（缩放/平移）          │ 检查器   │
│ 工作流    │                                        │ 节点 id  │
│ 搜索/分组 │                                        │ 块 / 参数│
│           │                                        │ 校验提示 │
├───────────┴────────────────────────────────────────┴──────────┤
│ 状态栏：3 errors · 编译通过 · 版本 v3 · 快捷键 · 保存/校验/运行 │
└───────────────────────────────────────────────────────────────┘
```

- **左**：块库 + 工作流列表；块库可搜索、按类别分组，拖入画布。
- **中**：画布；选中节点后右侧检查器改参数，不再跳到下方。
- **右**：检查器；只显示当前节点真正需要的字段，块说明与参数契约同屏。
- **底**：状态栏；脏状态、错误/警告、编译状态、当前版本、主操作。
- **上**：场景头；名称、归属（spec/code）、未保存标记、保存并验证。
- 基本信息、策略、版本、预览改成页签/抽屉，不再和画布抢纵向空间。

## 4. 交互规格

### 4.1 画布

| 操作 | 行为 |
|---|---|
| 拖块入画布 | 在落点创建节点，自动唯一 id |
| 拖节点 | 移动；松手才回传，拖动过程不 rerun |
| 从输出口拖到输入口 | 连线；重复边/非法方向给出即时提示 |
| 拖连线端点 | 重连，不必删了重画 |
| 点连线 / Delete | 删除；必须可撤销 |
| Shift+点 / 框选 | 多选；多选可整体拖动、删除、复制 |
| Ctrl+C / Ctrl+V / Ctrl+D | 复制/粘贴/副本；边尽量按引用保留 |
| Ctrl+Z / Ctrl+Y | 撤销/重做；至少 50 步，节点/边/位置都进栈 |
| 滚轮 / 空格+拖 / 中键拖 | 缩放 / 平移；工具栏有“适配视图”和“自动排版” |
| 双击节点标题 | 就地重命名 |
| 方向键 | 微调选中节点位置；Shift 加速 |
| Esc | 取消连线 / 取消选择 |

### 4.2 检查器

- 选中节点后显示：id、块类型、参数表单、块说明、校验错误。
- 参数表单由 `ParamSpec` 生成；`tool_list` 只能选场景工具白名单。
- 修改参数即时写入草稿，但不立即保存版本；状态栏出现 `未保存 ●`。
- 错误可点击定位：错误列表项 → 选中并居中对应节点。
- 不在节点框内塞表单：节点只显示中文名 + id + 块名，参数统一在检查器。

### 4.3 状态与保存

- **route 仍是唯一真相**：`?app=build&scenario=...&tab=structure`。
- 草稿按场景保存在 `st.session_state`；切场景不丢，顶部显示未保存状态。
- 可选：每次改动写 `data/runtime/spec_drafts/<name>.json` 做崩溃恢复；
  它不进 spec、不进 git，和 layout 一样是运行时数据。
- **保存**：校验 + 编译通过才生成新版本；失败不写盘，保留草稿与错误。
- 保存前可看 diff（新增/删除/改参数），默认折叠。
- **保存并验证**：保存成功后跑该场景一条 case（或 `--dry-run` 编译），
  在状态栏显示 pass/fail；这是编辑器接回评测主线的关键动作。
- 版本抽屉：列出 v1..vN、当前 active、载入到编辑器、与当前草稿对比。

### 4.4 反馈

- 画布错误节点红框 + 角标；悬停显示原因。
- 状态栏汇总 `N errors / M warnings`，点击展开列表。
- 编译通过/失败用固定位置的状态，不用 toast（演示时容易被忽略）。
- 破坏性操作（删除工作流、eject）二次确认；普通删节点靠撤销兜底。

## 5. 分阶段

### P0 实现状态（主体已完成）

- 三栏工作台：左工作流 + 块库（搜索/复合块分组，点块添加）；中画布/表单；右检查器；
  底部状态栏（未保存 / errors / 版本 / 撤销重做 / 校验 / 保存）。
- 画布：去掉 x=920 硬限制；滚轮缩放、空白拖动平移、工具栏 100%/+/-/适配；
  Delete 删选中节点（可撤销）；方向键微调（Shift 加速）。
- 撤销/重做：Python 侧 50 步栈，结构、边、参数、画布拓扑变更都进栈；
  撤销后换 widget 代次，保证表单显示回旧值。
- 草稿按场景保存在 session_state；未保存写 `data/runtime/spec_drafts/<name>.json`
  做崩溃恢复；切场景再切回不丢；`● 未保存` 与 `已保存` 在状态栏。
- 错误列表可点「定位」选中对应节点。
- **框选 / 多选**没有放进 P0：它属于 P1 的多选/复制能力，当前先做单选 + 撤销兜底。

#### 已知边界

- 画布位置变化不进撤销栈（位置在 layout 文件，不在 spec）；
- 撤销栈只在当前 session 内存里，刷新页面后清空；
- 画布仍是单文件 SVG，不引入 React Flow。

### P0 · 手感（先做）

1. 三栏工作台：左块库 / 中画布 / 右检查器；底部固定状态栏。
2. 撤销/重做、Delete、框选、方向键微调。
3. 画布缩放/平移/适配视图，去掉 x=920 硬限制。
4. 草稿按场景保存 + 未保存标记；切场景不丢。
5. 错误列表点击定位。

**验收**：选中节点 → 右侧改参数 → Ctrl+Z 撤销 → 切场景再切回，草稿还在；
画布可缩放到 50% 并平移；错误项点击能选中对应节点。

### P1 · 效率

1. 多选、复制/粘贴/副本、连线端点重连。
2. 块库搜索/分组、最近使用。
3. 保存前 diff。
4. **保存并跑一条 case**，状态栏显示结果。

**验收**：复制一个节点并保留其边；重连一条边不用删；保存后状态栏出现
`1/1 passed` 或失败原因。

### P2 · 演示加分

- 版本对比、条件边标签、简单 minimap。
- “演示模式”脚本：载入 `flow_demo` v1 → 删 `search` → 存 v2 →
  跑 case 失败 → 载回 v1 → 通过。把这条路径做成一键引导。

## 6. 明确不做

- 不把中间件顺序做成可拖拽（守卫不能变成表单）。
- 不在画布节点里塞完整表单（第二套 UI）。
- 不做代码 → spec 的反向生成。
- 不为了画布引入 React Flow / n8n 之类重依赖；现有单文件 SVG 组件先做
  选择、缩放、撤销，收益已经足够。

## 7. 知识缺口与参考

`frontend-design` 只覆盖视觉层级/间距/状态，不覆盖节点编辑器交互。需要补的是：

- **ComfyUI**：workflow JSON + 节点 schema 表单 + 队列，适合抄“数据/表单”边界。
- **n8n**：节点参数面板、撤销、执行预览。
- **React Flow**：选择/多选/连线/重连/minimap 的交互模型（只抄模型，不引依赖）。
- **Excalidraw / tldraw**：画布手感、键盘、撤销栈、框选。
- **Dify / Langflow**：DSL 与版本化，不抄它们的运行时。

DSH 插件里没有“节点编辑器交互”这个品类；`frontend-design` 已装，
`huashu-design` 可做编辑器外壳的视觉方向，`dsh-live-canvas` 可做 HTML 组件预览，
但都不是交互设计的替代。结论：**先不装新插件，写项目级 `editor-ux` skill +
本文件，作为后续 agent 的约束**。
