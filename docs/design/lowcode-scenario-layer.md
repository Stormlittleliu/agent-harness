# 低代码场景层：推迟决定与恢复计划

> 决定日期：2026-11-03
> 面试：2026-11-04 上午。**面试前冻结，不碰代码。**
> 一句话：方向成立，但现在不做；留一条可恢复的线索，别留一个半成品。

---

## 1. 决定

**不做，推迟到面试之后，且不排在第一优先级。**

三条理由：

1. **收益不在"能连线"**。低代码能编排节点拓扑，编排不了运行时策略（权限、超时、重试、预算、上下文压缩、HITL）。而后者才是这个项目可靠性的来源。
2. **成本不是一天**。spec schema + loader + 图编译器 + 前端 + 评测对齐，2–3 天起步；做到一半比不做更糟。
3. **当前瓶颈不在作者层**。缺的是评测样本、CI 接入、5–10 trial，不是编辑器。

**触发条件（满足任一再启动）：**

- 有非开发同事要改流程 / 加场景；
- 要复用到第二个业务或第二个团队（多租户）；
- 需要一个对外可演示的平台形态（作品集/汇报）。

都不满足时，它的优先级低于：CI 接入 > 5–10 trial + 区间 > rerank > 长期记忆 > 低代码。

---

## 2. 明天只说一句（不展开）

被问"有没有考虑做成平台/低代码"时：

> "场景层本来就是按可被外部编排设计的——Scenario 是声明式契约，工作流是编译好的 StateGraph，所以套可视化编排是加一个 spec loader，不用改架构。我没做，因为低代码能编排节点，编排不了运行时策略和评测；现在更值得先补的是评测和 CI。"

**不要**说"我准备接 Langflow"——那会把话题引到你没做过的集成上。

---

## 3. 恢复计划（每个阶段独立可用，可随时停）

### P0 · spec 化（半天）

- 定义 `scenario.spec.json`：name / tools（引用注册表）/ system_prompt / enable_* / graph 名 / cases 路径；
- 写 `build_from_spec(spec) -> Scenario`；
- 选一个最简场景（`router` 或 `workspace_assistant`）先跑通。

**验收**：删掉该场景 `scenario.py` 里的 `build_scenario`，只从 spec 构建，`cases.jsonl` 仍然全过。

### P1 · 图编译器（1–2 天）

- spec 里用"节点 + 边 + 工具白名单"描述工作流，编译成 `StateGraph`；
- 节点只允许引用**已注册函数**，不允许内联代码。

**验收**：从 spec 编译出的图，`draw_mermaid()` 与实际 compiled graph 结构一致；`deep_research` 能跑通并产出报告。

### P2 · 作者界面（2–3 天）

- Streamlit 表单产出 spec（先别做拖拽）；
- case 管理与 trace 回放接进来；
- 可选：导出给 Langflow 自定义组件，只当壳。

**验收**：不改代码，能在界面上加一个场景并通过 gate。

---

## 4. 四个必须提前定的约束

1. **spec 只描述结构，不描述代码**。节点是函数引用，否则会长出第二个 DSL。
2. **`schema_version` 必须版本化**，否则旧 spec 一改全废。
3. **中间件不进 spec**，只允许枚举开关（`enable_todo` 这种）。权限策略一旦可视化，就会被人改坏。
4. **同口径评测**：从 spec 构建的 Scenario 必须跑同一批 cases、产出同样格式的报告。做不到就是玩具。

---

## 5. 一句话

> 平台是**可替换的作者层**，契约和评测才是资产。先证明"不改代码也能安全加场景且评测仍然生效"，再谈低代码。
