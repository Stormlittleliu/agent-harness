- **所有数字统一口径**：DeepSeek + 本地 BGE；Qwen 时期的数据标注为历史，不混用。

## 3. 额外值得做的事（按 ROI 排序）

### P0：必须做

1. **统一指标口径**：所有数字用 DeepSeek + 本地 BGE 重跑；不要 Qwen 和 DeepSeek 混着说。
2. **一个失败分析**：拒答不足 / 严格 Prompt 导致答案完整性下降；这是最能体现工程思维的素材。
3. **2 分钟演示视频**：比现场翻代码稳定，面试官也更愿意看。
4. **10–15 个追问答案**：尤其是"为什么不用多 Agent""为什么本地 BGE""RAG 怎么评估"。
5. **两次模拟面试**：第一次找问题，第二次验证修复。

### P1：高价值

6. **3 个 case 的轨迹表**：步数、工具序列、延迟；证明你理解 trajectory eval。
7. **成本/延迟粗测**：3 个 case 的 token/耗时；体现生产意识。
8. **公司/JD 映射**：把 3 条 JD 要求对应到项目证据。
9. **行为面 STAR**：空窗、无实习、项目 ownership。
10. **GitHub/作品链接**：README 写清运行方式、评测结果、限制。

### P2：有空再做

11. 重跑 RGB 20 + MultiHop 12 全量公开基准；样本小，不作为核心数字。
12. 加 Rerank / Query 改写实验；**面试前不合并**，最多作为"下一步"讲。
13. 多 Agent / MCP / Skills demo；不在本周范围。

## 4. 面试时的数字口径

| 场景 | 说法 |

| Agent 用例 | "自建 13 条行为回归集，DeepSeek + 本地 BGE 下 11 条通过，工具调用 13/13 命中" |
| RAG 评测 | "自建 20/42 条评测集，检索看 Hit@4/MRR，生成看要点覆盖、引用、拒答" |

| 成本/延迟 | "目前只做定性优化，没有系统看板；这是下一步" |
