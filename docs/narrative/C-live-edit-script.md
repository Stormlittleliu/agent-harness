# 叙事 C：现场编辑一个服装域多路分流工作流

> 目标：8–10 分钟，现场证明「不用改代码，能新增/编辑结构，并且有多路分支」。
> 场景：在已发布的 **服装顾问**（`clothing_service`）里新建工作流 `apparel_triage`。
> 不新建第二个场景：控制台的「新建场景」默认给 office 工具箱，拿不到 `clothing_retrieve`；
> 服装工具在服装顾问里。这是产品边界，不现场硬演“复制场景”。

## 最短路径

```text
构建 → 场景库 → 服装顾问「打开 →」 → 结构
  → 新建工作流 apparel_triage → 新增
  → 加「分支判断」+ 2 个「检索」+「固定文本」
  → 表单模式填边和条件 → 保存为新版本
  → 发布 → 校验并发布 → 对话 → 服装顾问 → 试三句话
```

## 分幕与台词

### 0:00–0:30 开场

页面：控制台顶部产品切换到 **构建**。

> “今天不跑评测，也不改代码。我只用控制台，在服装顾问里加一条多路分流：
> 尺码、颜色、洗护各走各的，其他问题走拒答。全程只动 spec，保存后发布就能聊。”

### 0:30–2:30 打开并新建工作流

1. **构建 → 场景库**，找到已发布的 **服装顾问** 卡片，点 **打开 →**。
2. 顶部页签选 **结构**（`概览 / 结构 / 工具与策略 / 发布`）。
3. 左侧 **工作流** 下拉框现在是 `qa`。展开 **新建工作流**，在 **新增工作流名** 填 `apparel_triage`，点 **新增**。
4. 画布上应出现模板的三个节点：**检索**、**生成回答**、**引用校验**，边是
   `__start__ → search → answer → verify → __end__`。

> “新建工作流不是空白页，它给了最小可编译模板：检索 → 回答 → 引用校验。
> 我要做的是在前面加分流，在侧面加拒答；不需要从零摆节点。”

### 2:30–4:30 加多路 branch

1. 左侧 **块库**，搜索框输入 `分支`，点 **+ 分支判断**。
2. 画布上出现分支节点；右侧 **检查器** 里把 **节点 id** 改成 `triage`。
3. 在参数区填：
   - `field`：`input`
   - `cases`：`size=尺码|身高|体重|码, style=颜色|肤色|搭配|面料|外套, care=洗|养护|缩水|起球`
   - `default`：`other`
   - 旧版 `mode / keywords / hit / miss` 留空或保持默认；`cases` 非空时优先，旧参数不参与。

> “`cases` 是逗号分隔，不是 JSON 数组；每一项是 `route=关键词1|关键词2`。
> 三路显式命中，`default=other` 是兜底，不让‘退货’这种问题悄悄掉进服装检索。”

4. 画布上此时应看到 **分支判断** 节点，但出边还没接；先不要点保存。

### 4:30–6:30 接检索、回答、引用校验、拒答

模板已有 `search / answer / verify`。现在补齐三路检索和拒答。

1. 块库点 **+ 检索** 两次，分别选中后把 **节点 id** 改成 `style_search`、`care_search`。
2. 三个检索节点的 `tool` 都填 `clothing_retrieve`，`limit` 填 `4`。
   - 保留模板的 `search` 作为尺码检索；
   - `style_search` 颜色/搭配；
   - `care_search` 洗护。
3. 块库点 **+ 固定文本**，**节点 id** 改成 `refuse`；参数：
   - `text`：`我只处理服装相关问题：尺码、颜色、洗护和新品。`
   - `save_to`：`answer`
4. 左侧 **编辑方式** 切到 **📝 表单**。在 **边** 表里改成：

```text
__start__   → triage          （无条件）
triage      → search          size
triage      → style_search    style
triage      → care_search     care
triage      → refuse          other
search      → answer          （无条件）
style_search→ answer          （无条件）
care_search → answer          （无条件）
answer      → verify          （无条件）
verify      → __end__         （无条件）
refuse      → __end__         （无条件）
```

> “条件列必须和 branch 的 route 值一字不差：`size / style / care / other`。
> 编译器会检查：branch 可能写出 `other`，如果没有对应条件边，保存前就会报
> `可能写出 route=['other']，但没有对应条件边`。”

5. 切回 **🎨 可视化画布**，检查：
   - `triage` 节点四条出边分别带蓝色小标签 `size / style / care / other`；
   - 三条检索边汇到 **生成回答**，再进 **引用校验**；
   - `refuse` 直接到 `__end__`。

> “为什么不用 prompt 让模型自己分？因为 prompt 的分流看不见、也不能保证兜底；
> branch 是确定性的，route 写在状态里，条件边在画布上能看见，保存前还能静态校验。”

### 6:30–8:30 保存、发布、试聊

1. 底部状态栏点 **只校验，不保存**，应显示校验通过（或指出缺哪条边）。
2. 点 **保存为新版本**；顶部出现“已保存…新版本已设为 active”。
3. 切到 **发布** 页签：先点 **只校验（不写盘）**，再点 **校验并发布**。
   - 入口标题保持 **服装顾问**；
   - 如果出现“有未发布改动”，说明发布成功前结构仍是旧版本，重新发布即可。
4. 顶部产品切到 **对话**，左栏 **对话入口** 点 **服装顾问**，输入框是 **继续对话…（Enter 发送）**。

试三句话，覆盖三路 + 兜底：

| 输入 | 预期路径 |
|---|---|
| `身高170，体重110斤，推荐什么码？` | `size` → 检索 → 回答，带引用 |
| `黄皮适合什么颜色的外套？` | `style` → 检索 → 回答，带引用 |
| `你们支持七天无理由退货吗？` | `other` → **固定文本** 拒答，不检索 |

> “这三句分别证明：三路 cases 能命中、检索/回答/引用校验能接上、default 能兜底拒答。
> 结构不是画在 PPT 上，是保存成 spec 后发布到对话端跑出来的。”

### 8:30–9:00 收边界

> “今天只做结构编辑：不跑全量评测、不改代码、不新增块类型、不改工具池。
> 新建场景的默认工具箱是 office，所以服装工具我复用服装顾问；这是产品边界，
> 不是现场省略。要看已有成品，可以打开 **零售分流**，它的 `triage` 已经是
> 机器人 / 服装 / other 三路。”

## 现场话术：三个为什么

**为什么用 branch 而不是 prompt？**
> prompt 是模型自由裁量，分错了只能看回答；branch 把 `route` 写进状态，
> 条件边是图结构，保存前能静态校验，发布后能按 route 回查。可测、可审计。

**为什么 default 是 other？**
> 两个业务域不能把“退货/闲聊/其他”悄悄吞进服装检索；`other` 是显式兜底，
> 对应固定拒答。多一路 default，等于把“不处理”也变成结构的一部分。

**为什么这能证明编辑能力？**
> 全程只用块库、检查器、边表和发布页；没有改 Python、没有重启服务。
> 保存会生成新 spec 版本并设为 active，发布后对话端立刻可用。结构是数据，不是代码。

## Fallback：现场控件不配合

如果「新建工作流」或边表卡住，不要在现场 debug：

1. **构建 → 场景库**，打开 **零售分流**（`retail_router`）。
2. **结构** → **工作流** 选 `triage`，**编辑方式** 切 **🎨 可视化画布**。
3. 画布上应看到 `classify` 分支节点，出边标签为 `robot / clothing / other`。
4. 台词：
   > “现场控件没配合，但结构已经在 spec 里：`data/specs/retail_router/v1.json`
   > 的 `classify` 就是三路 branch + default。刚才要搭的 `apparel_triage` 用的是同一套
   > `cases / default` 语法，只是我把它换到服装域。”
5. 需要试聊就切 **对话 → 零售分流**，输入“退货”看 other 拒答，“扫地机器人回充失败”看 robot。

**fallback 不要做**：不要说“刚才已经保存了”；不要现场改 spec JSON；不要跑评测。

## 不现场做什么

- 不跑全量 selfbuilt / 不跑 3-trial；
- 不改代码、不重启；
- 不新增块类型、不改工具池；
- 不新建一个拿不到 `clothing_retrieve` 的空场景；
- 不为了“看起来成功”跳过校验。
